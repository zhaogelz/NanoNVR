# NanoNVR：更爱惜硬盘的监控录像机


https://github.com/user-attachments/assets/7b1013ee-f84c-44c4-ac6e-81868fe16fb0


> 让闲置 Windows 电脑变成本地 NVR。接入 RTSP 摄像头即可持续录像，旧片段会自动循环回收，磁盘也会保留安全空间。

## 📌 诞生背景

**想要装个监控，但这几个痛点劝退了很多人：**
1.  **室外储存卡不安全：** 装在室外的监控，如果只插储存卡，不仅因为风吹日晒坏得极快，而且一旦遇到坏人，直接连卡一起拿走毁尸灭迹，极不安全。
2.  **传统 NVR 太贵：** 购买专用的 NVR 录像机 + 监控级硬盘的组合成本实在高昂。

因此，我写了这个开源项目，**旨在将任何一台吃灰的闲置旧电脑 / 笔记本**，转化为轻量的**局域网监控录像机（NVR）**。

### 🛒 硬件选购建议（极简路线）
仅需购买**一台普通的监控摄像头**，接上网线或 Wi-Fi连接即可（前提是网络不能太差）。
*   **关键要求**：摄像头需要提供可访问的 RTSP 码流；推荐支持主/子码流和 **H.265**，它通常能在相近画质下降低码率和硬盘占用，但 H.264 同样可以录制。例如我测试过的型号是 `TL-IPC682F-A`。

## 为什么说它更爱惜硬盘

NanoNVR 兼容机械硬盘和固态硬盘。无论使用哪一种，它都会限制录像占用，避免磁盘被写满。使用机械硬盘时，程序还会尽量保持连续写入，减少反复扫描和零散清理。

1. **15 分钟切片直写**：摄像头已经编码好的视频通过 `-c copy` 追加到当前 MPEG-TS 切片，不生成视频转码临时文件。任一时刻主要写一个片段；15 分钟切片也兼顾文件数量与断电恢复范围。
2. **达到配额后成批回收**：录像配额是 100% 高水位，健康水位自动取配额的 90%。例如配额为 350 GiB 时，程序达到配额后会一次回收最老片段至约 315 GiB，减少清理触发、容量统计和目录遍历的频率。
3. **给录像和整块磁盘留余量**：除录像配额预留的 10% 回旋空间外，程序还检查整块磁盘的真实可用空间，最低保留 20 GiB 或磁盘容量的 5%（取较大值）。即使其他程序占用了磁盘，也会提前回收；若旧录像不足以恢复安全水位，程序会停止录制并提示处理。
4. **只回收确定安全的旧片段**：程序保护最新两个片段和正在导出的片段。清理完成后，它会重新测量录像占用和磁盘可用空间。这里只做文件删除并回收逻辑空间，不覆盖扇区，也不是所谓的物理抹除。
5. **录像进程随程序退出**：程序持续读取 FFmpeg 错误输出，避免异常日志堵塞录像进程；停止录制或关闭界面时，它会逐级回收 FFmpeg。Windows 下还使用 Job Object 托管录像与导出进程，降低界面退出后子进程继续写盘的风险。
6. **录像停滞后自动重连**：程序每 10 秒检查最新片段是否增长。连续 180 秒没有新数据时，它会结束 FFmpeg 并重新连接；主界面会显示最新文件和最近更新时间。

这些设计不会让同样码率的录像少写一遍。在机械硬盘上，它们主要用于维持连续的录像负载，减少零散维护。在固态硬盘上，它们主要用于控制空间占用，避免磁盘接近满盘；写入量仍由摄像头码率决定。

`-buffer_size 10M` 是 RTSP 网络接收缓冲，只用于应对网络抖动，不会减少写入硬盘的数据量。如果需要降低全年写入量和容量占用，应优先降低摄像头码率或选用 H.265。RAMDisk 也不能减少最终落盘的数据，反而会扩大断电时的录像损失范围，因此本项目不采用。

若保存目录位于专用的 24 小时录像机械盘，建议关闭该硬盘的频繁休眠，并定期查看 SMART 中的温度、启停次数、磁头加载/卸载次数、重映射扇区和待定扇区。NanoNVR 当前不修改系统电源策略，也不替代硬盘健康监控工具。

若使用固态硬盘，建议在硬盘厂商工具中查看健康度和总写入量，并继续保留足够空闲空间。NanoNVR 不修改 TRIM 设置，也不承诺延长某块固态硬盘的写入寿命。

### 软件能保护什么、不能保护什么

无论使用机械硬盘还是固态硬盘，NanoNVR 都能控制录像占用、防止磁盘逼近满盘、发现录像停止增长，并避免退出后遗留进程继续写盘。它不能修复硬盘，也不承诺延长具体寿命。降低总写入量仍要依靠摄像头码率和编码设置；温度、供电、震动、SMART 健康和备份仍需由用户负责。

## 🚀 极简使用方法

1. **下载运行**：从项目的 [Releases 页面](https://github.com/zhaogelz/NanoNVR/releases/latest)下载最新 `.exe`，放到旧电脑上双击运行。
2. **填入视频流**：在主界面的"RTSP 流地址"输入框中，填入您摄像头的主或子码流地址（例如 `rtsp://admin:password@192.168.1.100/stream1`）。
3. **设置录像配额**：在“录像配额(GiB)”框填入可循环录像的高水位（例如 `150`）。配额不能超过当前磁盘扣除安全余量后的容量；达到配额后会成批回收到 90% 健康水位，减少刚越线就反复清理。5 分钟巡检间隔和当前正在写入的片段可能造成短时小幅超出。导出文件不占用录像配额，但仍受真实磁盘安全余量保护。
4. **选择保存目录**（推荐）：在"保存目录"框指定录像与导出文件的存放位置，点「浏览…」选一块大容量硬盘即可。**留空则默认保存在程序所在目录**。显式填写的磁盘或目录不可用时，程序会阻止启动，不会静默回退到系统盘。录像 `.ts` 与导出 `.mp4` 都会落到这个目录下，统一管理。
5. **一键录播**：点击**"▶ 启动录制"**按钮。程序会自动保存参数自动录制。

> **⚠️ 关于播放与安全提示：**
> *   **回看原始 `.ts` 切片务必用 VLC**：为最大化省空间，NanoNVR 存的是**未转码的原始流**，系统自带播放器大概率无声或黑屏，请用 **VLC / PotPlayer** 等支持 H.265 的播放器打开 `.ts`。
> *   **导出的 `.mp4` 兼容性更好**：导出功能会把流重新封装进标准 MP4 容器，H.265 还会自动加 `hvc1` 标签。播放器或设备仍需具备对应的 H.264/H.265 解码能力，不能保证所有系统都可直接播放。
> *   **首次运行可能出现 SmartScreen 提示**：项目当前没有数字签名，Windows 可能显示“已保护你的电脑”。请只运行你自行构建或从本项目可信发布页下载的文件；代码签名可以降低此类提示，但项目当前未提供签名版本。
> *   **异地远程录制**：不要把带账号密码的原始 RTSP 端口直接暴露到公网。需要异地访问时，优先通过可信 VPN（例如自建 WireGuard）让录像机与摄像头进入受控私网，并限制可访问设备；无论采用哪种方式，都应更换默认密码并做好访问控制。

## 📤 导出录像为 MP4

平时回看用 VLC 直接打开 `.ts` 切片即可；如果需要把一段录像发给别人或在手机上播放，可以用内置的导出功能把它合并成单个 MP4：

1. 点击主界面**「📤 导出录像」**按钮。
2. 选择**录像日期**，再选择**开始分片**与**结束分片**（结束分片会被完整包含）。
3. 确认保存路径（默认 `exports/日期_起-止.mp4`），点击**「开始导出」**，底部进度条会实时显示进度。

**导出是"无损转封装"，不是重新编码**：画面数据直接 `copy`，速度接近文件拷贝，画质零损失，导出几十个切片通常只需几十秒。程序会在导出前自动探测流的编码格式并做兼容处理：

| 探测到的情况 | 自动处理方式 |
| --- | --- |
| 视频 H.264 / H.265、音频 AAC | 全部直接 `copy`，纯封装，最快 |
| 音频是 G.711 / G.726 等（摄像头常见） | **仅重编码音轨为 AAC**，画面仍无损 `copy` |
| 视频是 H.265 | 自动打上 `hvc1` 标签，保证 QuickTime / 部分播放器能识别 |
| 无音轨 | 直接产出纯视频 MP4 |

> **💡 几点说明：**
> *   **时间粒度为 15 分钟**：切片是按 15 分钟整段存的，导出也必须以切片为单位起止，这样才能保证 `copy` 模式下不花屏（因此结束分片会被完整包含，实际时长可能比选的多出最多 15 分钟）。
> *   **最新分片不会参与导出**：分片文件名取 FFmpeg 的实际开始时间，不保证落在整刻钟。录制期间导出当天录像时，程序会按真实文件顺序排除最新分片，避免读取仍在增长的文件。
> *   **导出文件不会计入录像配额**：`exports/` 里的 MP4 是用户主动保留的产物，自动清理永远不会删除它（只回收日期目录下的 `.ts` 分片）。它仍会占用所在磁盘的真实空间；导出过多导致磁盘低于安全余量时，程序会先回收旧录像，仍无法恢复时会停录并提示你转移导出文件。
> *   **机械盘建议导出到其他磁盘**：大量读取旧片段并把 MP4 写回同一块机械盘会增加磁头寻道。需要频繁或长时间导出时，请点击“浏览...”把输出路径选到其他磁盘。

### 📂 录像文件保存在哪里？

录像文件保存在您**「保存目录」所指向的位置**（未设置时默认为 **NanoNVR.exe 所在的同级目录**）。建议选择一块容量充足的机械硬盘或固态硬盘，避免把系统盘写满。目录结构如下（直接用 VLC 或 PotPlayer 打开 `.ts` 即可回看）：

```text
【保存目录】（默认 = NanoNVR.exe 所在目录，可在界面修改）
├── 2026-03-01/           # 【按日期自动归档文件夹】
│   ├── 08_00_00.ts       # 08:00 开始的 15 分钟录像切片
│   ├── 08_15_00.ts       # 08:15 开始的 15 分钟录像切片
│   └── ...
├── exports/              # 【导出功能产出的 MP4】
│   └── 2026-03-01_08-00-00_12-00-00.mp4
└── ...

注：NanoNVR.exe 本体、config.json 与 ffmpeg 始终在 exe 所在目录，不随保存目录移动。
```

## ✨ 其他无门槛优势

*   **🧰 单文件运行**：自带直观的 GUI 并支持一键打包。目标电脑无需安装 Python 或配置环境变量，复制打包后的 `.exe` 即可运行。
*   **🔄 自动断线重连**：网络中断或摄像头重启后，程序会记录 FFmpeg 的退出信息，并按间隔重新拉流；断线期间会存在录像空档。

## 📦 拿到别的电脑用（分发方式）

打包产物是**单文件 `.exe`**，FFmpeg 已经连同程序一起被封进去了，所以分发极其简单：

1. 把 `dist` 目录下的 **`NanoNVR.exe` 单个文件**复制到目标电脑（U 盘、微信、网盘都行，约 80MB）。
2. 双击运行即可，**目标电脑无需安装 Python、无需安装 FFmpeg、无需配任何环境变量**。
3. 录像会保存在 **exe 所在的同级目录**下，所以建议先在目标电脑上**新建一个空文件夹**（比如 `D:\监控录像`），把 exe 放进去再运行，方便管理。

> **注意**：换电脑时**不要复制 `config.json`**（里面是旧电脑的 RTSP 地址和密码），程序会在新电脑上自动生成一份新的。

## 🛠️ 打包编译指南 (供开发者)

如果对代码进行了二次修改，需要重新打包给其他纯净系统使用：

1. 确保当前环境已安装 Python 与 `pyinstaller`。
2. 确保 `ffmpeg.exe` 位于 `recorder.py` 旁边。
3. 双击运行 `build_exe.bat` 进行自动编译封装。
4. 编译完成会自动打开 `dist` 目录，提取生成的独立执行文件即可。
